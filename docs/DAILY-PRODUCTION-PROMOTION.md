# Daily production releases and low build cost

Development PRs target main. Only the daily promotion workflow writes live. Its primary attempt is 00:01 America/Denver (12:01 a.m. local time, including daylight saving changes). Because GitHub may delay or silently drop a schedule event, the workflow also fires at **00:17, 01:17 and 05:37 America/Denver, plus 12:43 UTC**, as same-night missed-trigger recovery windows, not additional releases. Every attempt invokes the same exact-main six-check gate and atomic fast-forward with a dated Colorado-day tag. The gate matches each required check by its posted name, including matrix shard names (`unit (1)`…`unit (3)`, `db (1)`…`db (2)` since the CI-SPEED sharding, PR #309): every posted shard name's latest run must be green, and the `ci` summary check in the same list proves every shard ran. (Before this matching repair, the first recovery attempt on 2026-11-04 waited out its window and refused, because no check is posted under the plain names `unit`/`db` anymore.) A successful promotion consumes the day marker, so later attempts skip even if development advances main; unchanged heads also skip. Failed/missing checks, divergence and consumed day markers refuse release. The only manual path is an owner-only `workflow_dispatch` recovery of the same workflow (`recover_missed_daily`, with both the actor and the triggering actor required to be `christcr2012`) running the same checked promoter. No force-push fallback.

Owner-directed verification on 2026-10-12: Vercel Production Branch Tracking is live, and Preview Branch Tracking is disabled. vercel.json also disables Git deployments on every branch except live, including slash-named branches. Vercel settings apply to the linked project now; the repository rule protects future configurations. GitHub CI and existing offline/SQL/HTTP checks continue without a paid deployment requirement. Do not run Vercel CLI production deployments, promote previews, or release at a development batch boundary without a separate explicit owner instruction.

The live branch was provisioned from the previously verified deployed commit before the workflow was enabled. If live is deleted, restore the last verified released SHA deliberately rather than silently recreating it from main. Review Actions → Daily live promotion after the next scheduled run; verify the marker and live ref, then the Vercel deployment's source and status. No production build is triggered merely to test this cost change.

This does not enable Stripe LIVE, money movement or production-account access. All existing owner gates and deployment protection remain unchanged. Production requests, subscriptions, storage, database use and retained sandboxes can still incur charges; disabling builds does not erase billed usage.
