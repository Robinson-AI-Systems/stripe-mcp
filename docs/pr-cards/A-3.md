## A-3e — bounded dynamic registration input (PR #146)

In public OAuth registration, reject oversized redirect URI strings,
invalid client names and unsupported response/grant declarations before
creating any durable client. In the shared HTTP parser enforce the 16 KiB
body limit equally for already-parsed objects and raw body strings.
No change to client scopes, TEST-only modes, owner authentication, DB schema,
external TEST-account acceptance or live policy.

Tests: `tests/unit/oauth-handlers.test.js` for rejected/accepted registration
metadata and secretless refusals; `tests/unit/http-body-limits.test.js` for
oversize/circular and normal input; complete CI and documentation checks.

## A-3f — RFC 7591 default confidential client authentication (PR #148)

Registration requests that omit `token_endpoint_auth_method` now produce
`client_secret_basic`, the standards-based default for new confidential
clients. Explicit `client_secret_post` and `none` remain fully supported;
persisted existing POST clients retain their exact method and scope. Empty,
null, or unknown method declarations are rejected instead of silently reset.
Owner passphrase, resource targeting, S256 PKCE, TEST scope, hashed secrets
and refresh rotation remain unchanged. No database migration or Stripe call.

Unit tests: default Basic full code-exchange/refresh, refused body secret,
explicit legacy POST/public registration and malformed-method refusal, plus
existing OAuth and mock/db suites. External browser connection and Vercel
SSO acceptance remain **pending** despite green automated tests.
