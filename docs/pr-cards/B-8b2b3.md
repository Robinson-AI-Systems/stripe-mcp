## Contract
- The standing schema default remains **$500 USD/account/Colorado day**.
  The owner sees the selected account, existing cap, proposed cap and any
  current daily usage as a dollar preview before any change.
- Changing the configured cap must require the private owner form with
  strict origin, CSRF, lockout, independently re-entered passphrase,
  explicit final acknowledgement, short expiry and one-use audit.
- The AI cannot change caps by supplying `confirm`, `ownerApproved`
  or a forged MCP argument. No public write door until its seven guard
  cases and separately authenticated owner controls pass.
- Account-scoped SQL must reject stale expected cap, overflow, unrepresentable
  amounts, cross-account calls and concurrent approval races. Money values
  remain safe integer cents, human preview is in dollars and cents.
- **A cap change NEVER waives individual owner approval for an AI-initiated
  money-out.** Requests exceeding the then-configured cap still need a
  second explicit owner override for the exact same transaction. No blanket
  authority is created or stored.
- Do not silently raise the approved $500 standard as part of deployment.
  The owner alone may explicitly elect a different per-account limit via
  the verified flow; preserve decision/audit evidence.
- No provider LIVE operation, no payment, no additional infrastructure.
