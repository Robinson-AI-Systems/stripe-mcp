## Scope
- Add explicit provider-derived stable `target` identity to each pending
  money-out request. Do **not** accept a target derived only from untrusted
  agent input or a free-form display string. The trusted tool's read/prep
  stage must supply it; if missing/ambiguous, refuse owner approval.
- Bind account, tool, exact target, server-derived integer USD amount,
  idempotency request key and expiry. Repeated request keys that change
  any one field must fail closed; protect legacy rows without a verified
  target from approval.
- Owner-only pending request list must be reached through private POST
  with independent passphrase, strict origin, CSRF and rate-limiting;
  never reveal key hashes, secrets, raw provider data or other accounts.
- Include exact status/age and shared daily cap and usage for owner review,
  formatted in dollars/cents and Colorado time; page responses no-store,
  credentials and request details escaped.
- Tests use fake provider-derived Stripe IDs and disposable localhost
  PostgreSQL to prove cross-account privacy, target mismatch/replay,
  missing/expired requests, safe limits, and absence of owner grant.
- Do not register public money write tools, enable live, move real funds
  or provision infrastructure.
