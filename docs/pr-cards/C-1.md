## Boundaries and completion
- Add `result_store` (handle, opaque connection scope, expires, safe JSON body,
  summary) and persist a stable opaque scope alongside existing OAuth token
  rows. Existing refresh updates the row and retains scope. Database cleanup
  deletes only a bounded batch of expired handles per request.
- Create `src/tools/summaries.js` with safe object type summaries, and
  `src/tools/result-rules.js` with validated dotted fields, detail behavior
  and bounded chunk/preview. Unknown fields get a note, never a silent drop.
- In `dispatchReadOnlyTool`, shape/redact before persisting, validate the
  authenticated result scope, never let caller supply it. If result is
  oversized, save a scoped handle with 24h TTL and return the first part.
- Register `stripe_get_result` READ tool to retrieve scoped paged results;
  no credential/result from a different OAuth connection, even when the same
  client/account is used. Unknown or expired handles denied. No write door.
- Keep all results ≤8 KB including metadata. Existing account tools remain
  backward compatible; new area tools use reusable summaries/fields by default.
- Unit: summaries and projection edge cases, unknown paths, size/unicode;
  annotations, default ≤8 KB. DB: real throwaway localhost PG schema, concurrent
  same-connection handle, account/client isolation, expiry and refresh scope.
