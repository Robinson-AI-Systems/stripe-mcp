## Provider and permission boundaries
- Methods to verify against pinned Stripe OpenAPI: customers.list,
  retrieve, search, create, update, del; paymentMethods.list/retrieve/detach;
  customer balance transactions list/create; taxIds list/create/del;
  discount delete; default invoice_settings update. Never expose payment
  method secrets, API key or provider client_secret.
- Read-only `customer_list/get/search/find` and payment-method/credit
  history should work with a verified TEST-only server-side key.
- Write tools inherit `src/tools/write.js` guard, app-owned detection and
  audit; no cross-profile, cross-account, or LIVE execution. Monetary balance
  credit must use owner-bound money guard if direction moves funds.
- Verify D0 provider expectations before touching invoice/subscription
  follow-ons; absent Stripe operations trigger reviewed design amendment,
  never a guessed endpoint.
