## Work and risk boundaries
- Sixteen current-native tools: hosted customer pay/session/setup links,
  Checkout session list/get/line items/expire, payment links list/get/
  create/update/deactivate/activate, portal session and configurations
  list/get/update.
- Saving card/bank uses **hosted Checkout setup mode** with card and US
  bank account only; `client_secret` never appears in any tool output.
  Do not implement deprecated raw setup-intent secret/client flows.
- Never invent customer consent, prices, approved return domains or
  Stripe Dashboard-wide branding. Use the provider's pinned SDK and
  owner-configured redirect allowlist; fail closed if absent. Return
  only hosted URL, safe expiry and masked metadata.
- Read-only calls permitted to verified read_only connections. Mutations
  must reuse `defineWrite-v1`, app ownership, preview/confirm,
  idempotency and verified read-back. TEST only; owner full profile and
  explicit confirmation for portal policy changes.
- A payment link or Checkout session merely **offers** a hosted payment:
  creating one must not falsely count funds as captured/paid, release
  money or bypass external money-out owner approval. No LIVE/real
  Stripe action (IN-06 still OFF). Catalog ownership and price integrity
  respect app-managed resources.
- Verify pinned official Stripe SDK methods against disposable
  stripe-mock, including nested `line_items`, setup card/US bank types,
  session vs reusable link semantics, refund-safe redaction and portal
  configuration changes.
- Run seven-case contract matrix for every write, direct/read_only/LIVE
  and indirect stripe_call/batch gates, and output/secret tests.
  Merge exact-head `ci` (check/unit/db/mock/aggregate) with no unresolved
  review threads. Update card, catalog, STATUS, PLAN/ROADMAP,
