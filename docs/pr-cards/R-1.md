### Critical security boundary

A pass is an **owner-issued user delegation**, not an implicit builder TEST credential. Issuance is owner-authenticated; bearer passes never sign in to MCP or get an API key, and the service keeps provider account/grants state. Explicit money-out still goes through original owner separately authenticated exact target/amount approval and configured account cap (pass $0 is the *default*, not a permanent product limit). Any pass-level spending cap must be atomically enforced, not merely displayed. LIVE passes cannot bypass private two-step account activation, verified live credentials and separate authenticated owner passphrase. No real TEST provider mutation, money spending, server config override, production release or LIVE reactivation permitted during this engineering session. Missing external owner acceptance is tracked honestly.
