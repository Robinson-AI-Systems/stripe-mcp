## Drift A (reconciled after V-4a)
| Approved assumption | Observed repository/provider state | Reconciliation |
| --- | --- | --- |
| HTTPS target alone is secure | Node can follow private DNS answers or redirects | V-4a pins a globally verified public TLS address; V-4c must refuse redirects |

## Goal
Allow an authorized developer to register an HTTPS endpoint and replay precisely selected original Stripe TEST Events, signed like Stripe webhooks, without the Stripe CLI. Never invent a Stripe event, leak a secret, contact private addresses, write LIVE records or imply webhook delivery without exact HTTP response.

## Slices
1. **V-4a — merged #67.** Public HTTPS DNS/IP guard, verified IP pinning contract, official HMAC signature equivalence (Stripe constructEvent), no sends.
2. **V-4b1 — current.** Durable per-account forwarder table and encrypted secret slot, immutable requestKey/digest, owner-scoped projections and soft-delete. No public tools.
3. **V-4b2.** Guarded TEST create/list/delete tools, owner-authenticated one-time setup-page secret issuance/reveal. Never emit raw secret in a tool/result/audit/log. Ensure read-only and other profiles do not widen.
4. **V-4c.** Bounded original TEST Event ID/time/type selectors, independent Stripe retrieval/provenance, secure pinned TLS HTTPS POST, no redirects, per-event status and replay outcome, no false webhook delivery inference.
5. **V-4 acceptance.** Verify official Stripe constructEvent with byte-exact body, target refusal including DNS rebinding, durable secret rotation/reveal rules, no live/app-owned crossing, disconnected/uncertain responses and audit safety.

## Guardrails
No old-toolkit integrations or agent compatibility, no new spending. No LIVE writes, money-out, app-owned mutation or plaintext secret exposure. A missing production enrollment is not an excuse to fabricate a provider acceptance result.
