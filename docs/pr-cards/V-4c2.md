## Drift A
| Assumption | Actual main | Decision / coverage |
| --- | --- | --- |
| Retrying a webhook is harmless | A POST can succeed before its response is recorded | Atomic replay/event reservation; mark 'uncertain' before any network call; same retry key never sends again |
| A single batch can prove all selected events reached the app | V-4c1 proves only target HTTP response | Persist exact event IDs and 2xx/3xx/4xx/5xx status; never claim app processing |
| A replay to another Stripe account could use the same forwarder ID | V-4b1 queries are scoped by Stripe account | Every public, internal and SQL operation checks selected account + forwarder |
| Retrying a time-selected window is stable | Events.list can gain new results | Bind immutable digest to exact retrieved event IDs and selector; changed selection refused |

## Files and contract
- src/dev/forwarder-replay-store.js: atomic event and replay reservations, account-scope, immutable digest, terminal HTTP receipt persisted once.
- src/tools/dev-forward-events.js: guarded defineWrite-v1 TEST-only dev_forward_events.
- src/db.js: additive tables, no raw event bodies, no ciphertext or plain secret in receipts.
- src/tools/index.js: one developer write tool, registration and profile counts updated.
- Production decrypts private signing secret only within guarded apply; nobody can supply a secret through MCP. No Stripe write is performed.
- V-4a and V-4c1 deliver strict TLS verification, fresh all-answer DNS validation, no redirects and byte-exact Stripe Signature.
- Same requestKey with prior reservation returns durable receipts, never automatically re-POSTs. To intentionally replay, owner must preview/confirm a NEW requestKey.
- Failed and unknown outcomes are surfaced as rejected / uncertain, never upgraded to accepted.
