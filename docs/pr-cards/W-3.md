## Safety and verification

Root workflow confirmations MUST NOT elevate the account/profile, app ownership, native write or independent owner money-out approval. The original `payment_create_refund`, `billing_cancel_subscription`, and `invoice_void` native guarded handlers are the ONLY provider write avenues. No direct SDK operation or mutable global cross-request state. Never replay an uncertain child automatically. A one-preview multi-action plan is a bounded sequence, **not** atomic; record real partial completion and operator next actions. No LIVE, no real funds, no autonomous spend or forced release.

Evidence and delivery measurements will be added with the actual outcome; code/CI alone cannot count protected real-provider acceptance. W-3/W-4 may legitimately return an independent owner-approval denial on actual connected TEST instead of triggering a refund.
